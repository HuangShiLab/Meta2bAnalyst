# 教程 2: 数据格式详解

> 目标时长：10 分钟
> 目标受众：准备使用 Meta2bAnalyst 进行数据分析的研究者
> 目标：理解各种输入格式的要求和数据准备方法

### 第一部分：通用格式要求（0:30-2:00）

#### 特征表通用格式（0:30-1:15）

**[画面]**：文本编辑器展示特征表 CSV 文件内容，高亮关键行和列

**[解说词]**：
> "首先，无论您使用哪种工具，特征表都有一些通用格式要求。第一行必须以井号 NAME 开头，后面跟着所有样本名。第一列是特征名，比如 OTU 编号、物种名称或者基因编号。数据区域必须是整数，表示丰度计数。"

**[画面]**：展示正确的特征表示例，然后展示常见错误示例（红色高亮）

**[解说词]**：
> "这是正确的格式示例。注意样本名不要包含空格，不要用特殊字符。常见错误包括：第一行缺少井号 NAME 标记；样本名大小写不一致，比如特征表用 Sample 大写 S，元数据用小写 s；数据区域包含小数或空值。这些问题都会导致上传失败。"

#### 元数据通用格式（1:15-2:00）

**[画面]**：展示元数据 CSV 文件示例

**[解说词]**：
> "元数据的格式和特征表类似。第一行同样以井号 NAME 开头，后面接样本名。第一列是样本名，必须和特征表中的列名完全一致。后续列是分组变量。这里有一个重要的统计要求：每组至少要有三个重复样本。如果某组只有两个样本，系统会提示无法进行统计检验。"

**[画面]**：展示分组变量预览，强调每组样本数

**[解说词]**：
> "比如这个示例中，Control 组有 15 个样本，Treatment 组有 15 个样本，满足统计要求。如果某组只有一两个样本，建议合并小组别，或者重新设计实验。"

### 第二部分：2bRAD-M 格式（2:00-3:30）

**[画面]**：展示 2bRAD-M 工具输出文件的目录结构

**[解说词]**：
> "2bRAD-M 是 2bRAD 工具群的核心模块，输出物种丰度表、功能基因表和元数据。对于物种水平分析，您需要上传 species abundance CSV 和 metadata CSV。"

**[画面]**：打开 species_abundance.csv 文件，展示内容结构

**[解说词]**：
> "species_abundance.csv 的每一行代表一个物种，列是样本名。数值是物种的 reads 计数。这个文件可以直接用于物种水平分析。"

**[画面]**：打开 metadata.csv 文件，展示内容结构

**[解说词]**：
> "metadata.csv 包含样本的分组信息。您可以根据实验设计添加多列分组变量，比如 Treatment、Site、Time 等。Meta2bAnalyst 会自动识别所有分组变量供您选择。"

**[画面]**：展示可选上传的功能基因表和株水平表

**[解说词]**：
> "如果需要进行功能基因分析，可以上传 functional_genes.csv。如果上传了 strain_profile.csv，还可以进行株水平分析。这些文件都是可选的，根据您的分析需求选择上传。"

### 第三部分：QIIME / BIOM 格式（3:30-5:00）

**[画面]**：展示 QIIME 2 输出文件目录结构

**[解说词]**：
> "QIIME 2 是微生物组分析中最常用的流程之一。Meta2bAnalyst 支持 QIIME 2 的 BIOM 格式特征表。您需要上传 feature-table.biom 和 metadata.csv。"

**[画面]**：展示如何在 QIIME 2 中导出 BIOM 文件

**[解说词]**：
> "如果您有 QIIME 2 的 qza 文件，需要先导出为 BIOM 格式。使用命令 qiime tools export 导出 feature table。确保导出的 BIOM 文件是 HDF5 或 JSON 格式。"

**[画面]**：展示 BIOM 文件上传和 taxonomy 文件上传

**[解说词]**：
> "上传 BIOM 文件和元数据。如果有分类注释文件 taxonomy.tsv，也可以一并上传。taxonomy 文件帮助系统进行物种注释和分类层级展示。如果没有上传，系统会使用特征 ID 作为默认名称。"

**[画面]**：展示 QIIME 元数据格式要求

**[解说词]**：
> "QIIME 的元数据格式有一个特殊要求：第一列必须是样本 ID 列，列名通常叫 sample-id。Meta2bAnalyst 会自动适配，但请确保样本 ID 和 BIOM 表中的样本名一致。"

### 第四部分：Mothur 格式（5:00-6:30）

**[画面]**：展示 Mothur 输出文件（.shared 和 .taxonomy）

**[解说词]**：
> "Mothur 是另一个经典的微生物组分析工具。Meta2bAnalyst 支持 Mothur 的共享文件和分类注释文件。"

**[画面]**：打开 .shared 文件，展示内容结构

**[解说词]**：
> "shared 文件是 Mothur 的 OTU 表。第一行是标题行，包含标签、分组和 OTU 列。数据行中，每一列代表一个 OTU 在每个样本中的计数。上传时选择所有样本的 shared 文件，Meta2bAnalyst 会自动合并。"

**[画面]**：打开 .taxonomy 文件，展示内容结构

**[解说词]**：
> "taxonomy 文件包含每个 OTU 的分类注释。格式是 OTU 名称、大小和分号分隔的分类层级。请确保分类层级完整，从界到种。"

**[画面]**：展示 Mothur 文件上传界面

**[解说词]**：
> "上传时选择 shared 文件和 taxonomy 文件，以及元数据。Meta2bAnalyst 会自动解析 Mothur 格式，提取 OTU 表和分类信息。"

---

### 第五部分：通用 CSV/TSV 格式（6:30-8:00）

**[画面]**：展示通用 CSV 格式示例

**[解说词]**：
> "如果您的数据来自其他工具，或者已经在外部处理过，可以使用通用 CSV 或 TSV 格式。这是最灵活的格式，只需要满足基本的特征表和元数据格式要求。"

**[画面]**：展示从 Excel 导出 CSV 的过程

**[解说词]**：
> "很多研究者用 Excel 整理数据。从 Excel 导出 CSV 时，请注意：选择 UTF-8 编码；使用逗号分隔；不要包含合并单元格；删除多余的格式和颜色。"

**[画面]**：展示 R 语言导出 CSV 的代码

**[解说词]**：
> "如果您用 R 语言处理数据，可以用 write.csv 函数导出。确保设置 row.names 等于 FALSE，避免行名被写入第一列。如果第一列已经是特征名，请使用第一列作为名称。"

**[画面]**：展示 Python pandas 导出 CSV 的代码

**[解说词]**：
> "如果您用 Python，可以用 pandas 的 to_csv 方法。同样设置 index 等于 False，避免索引被写入。header 参数设为 NAME 作为第一行标记。"

---

### 第六部分：数据检查与修正（8:00-9:30）

**[画面]**：展示数据验证失败的错误提示页面

**[解说词]**：
> "上传数据后，系统会自动验证。如果验证失败，请根据错误提示修正。最常见的错误是样本名不匹配。"

**[画面]**：展示样本名不匹配的错误示例和修正方法

**[解说词]**：
> "样本名不匹配通常是因为大小写不一致或空格问题。建议在准备数据时统一使用小写字母和下划线，避免空格和特殊字符。比如 sample_1、sample_2 这样的命名规范。"

**[画面]**：展示分组样本数不足的错误提示

**[解说词]**：
> "如果提示分组样本数不足，说明某组少于三个样本。请检查元数据中的分组变量，确保每组至少三个重复。对于只有两个样本的组，可以合并到相邻组，或者从分析中排除。"

**[画面]**：展示数据概览统计页面，解释稀疏度概念

**[解说词]**：
> "数据检查页面的稀疏度指标表示零值在矩阵中的比例。如果稀疏度超过 90%，说明数据非常稀疏，可能需要在上游分析中调整参数，或者在本平台使用更严格的过滤。"
